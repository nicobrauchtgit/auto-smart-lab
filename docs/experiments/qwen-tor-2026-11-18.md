## Correction: the minimal label fix never reached the minimal chain (2026-11-18)

The Google observer found this, and it was verified here. `--continue` runs the agent code copied into the chain at creation (`runs/minimal/2026-11-11T08-29-56/agent/`), not `harness/minimal/agent/`.

- **What actually ran:** the chain's `agent/run/output_check.ts` still enforces `<id>;<integer>` (regex `/^([^;]+);(-?\d+)$/`), and its `agent/instructions/solver.md` is still `ebb246c7…`. Updating `chain-version.json` promptHash only satisfied the continuation guard; it did not deploy the fix.
- **What that means:** website names would have been refused. The agent's code comment ("The harness only accepts `<id>;<integer>` lines") was correct, and the index delivery was forced by the harness, not an agent error.
- **Outcome re-labelled:** minimal tor1 is now `delivered_indices_forced_by_undeployed_label_fix`. The site-name conversion above is the correct answer.
- **minimal tor2 was unaffected** (0/1 labels).
- **Chain left as evidence:** the chain copy is unchanged, and no further minimal runs are planned. `chain-version.json` now records `0a3ff4c0…` while the chain's `solver.md` is `ebb246c7…`; see the correction in `chain-version-receipt.json`.
