- **Inputs are flat single-blob text files, not MIME.** Every member (train and test) is one plain-text document whose first line is `Subject: …` and whose remaining lines are the message text; there is no blank-line header/body split (`profile.training.text.email_header_rate` = 1.0, `profile.test.text.email_header_rate` = 1.0; blank-line presence only 0.020 train / 0.019 test — `research/probe1.py`).
- **Names are inside the zip**: `spam1-train.zip` has 16,663 members including `spam1-train.labels` (`probe1.py` namelist vs `profile.training.inventory.samples` = 16,662) — exclude it when iterating. `spam1-train.labels` is `data/spam1-train/<name>.<k>;<k>`, 16,662 lines, and the numeric name suffix matched the label in every line spot-checked.
- **Text is pre-normalized**: lowercased with spaces inserted around punctuation (`http : / / www . wellsfargo . com`, `- - -`, `e - mail`). Consequence: the profile's URL metric is useless — `urls` mean 0.0 in both splits (`profile.*.text.urls`) although 18.0% of test docs contain `http : / /` (`probe1.py`; raw `http:` never matches).
- **Class balance and leakage are clean.** Train 8,360 ham / 8,302 spam (≈50/50, `profile.training.targets`), no duplicate contents inside either split, 0 exact content matches between train and test (`profile.*.duplicates`, `profile.training_vs_test.exact_overlap`), and target rate flat across archive order (`profile.training.order_leakage`).
- **Near-duplicate check gives no shortcut either**: md5 of the sorted token multiset produced 0 train∩test collisions, and md5 of the sorted first 150 tokens only 6/15,051 (`research/probe4_dup.py`).
- **Vocabulary transfers well**: 133,417 distinct alphabetic tokens in training, mean 217.5 tokens/document; 46,788 with count ≥3; mean OOV rate on 800 sampled test docs is 0.075 (median 0.051) (`research/probe5_vocab.py`).
- **Training ham is Enron-corpus-specific**: `ect` appears in 3.76% of ham and 0% of spam, `enron` 3.07%/0%, `hou` also ham-only (`probe5_vocab.py`), and `hou / ect|ect / enron` occurs in 0.296 of train-ham but only 0.036 of test, `forwarded by` 0.260 ham → 0.031 test (`research/probe3.py`). A feature set that leans on these ham markers is a train/test-shift trap: spam-side rates, by contrast, line up with roughly the usual mix (e.g. `viagra` 0.037 test vs 0.000 ham / 0.063 spam).
- **Strong observed per-class contrasts (train, ham/spam rate)**: `viagra|pharmac|medic` 0.004/0.183, `$` 0.124/0.333, `click` 0.049/0.205, `unsubscribe|opt - out` 0.007/0.074, `enron` 0.595/0.0, `- - forwarded by|fwd:|fw:` 0.277/0.029, `@` 0.501/0.269, lowercase mid-document `subject :` 0.424/0.010 (`research/probe1.py`, `probe3.py`).
- **Length tail differs sharply between splits**: test mean 1,808 B, max 228,386 B vs train mean 1,460 B, max 27,966 B (112 test docs >20 kB vs 7 in train, and 95% of them mention "enron"; `profile.test.sizes`, `profile.training.sizes`, `probe2.py`); test line count max 2,648 vs train 517 (`profile.test.text.lines`). Within train, size is essentially class-neutral (mean 1461.9 vs 1459.1, `profile.training.sizes_by_target`), so size-like features move out of distribution on test.
- **Encoding trap, partly a profile artifact**: profile flags 11 train / 28 test members as "binary" with `utf8_fraction` 0.9993/0.9981, but full-member UTF-8 decoding succeeded for all 16,662 + 15,051 files (`probe2.py`) — the flags come from its 4 KiB-prefix heuristic. Real oddities are stray NUL bytes inside otherwise readable spam (11 train, 29 test, e.g. `data/spam1-train/eagmgkgbesxvaxgs.1` with NUL-only lines) and high non-ASCII bytes in 3.7% train / 4.3% test (`probe1.py`); decode leniently.
- **No HTML, no capitalization signal, no binary payloads**: HTML markers ~0 (`profile.*.text.html_rate` 0.0001/0.0), no `<a href>`-style tags or base64 blocks found (`probe1.py`, `probe2.py`); every member contains at least one `[A-Z]` byte but the body is otherwise lowercase (`probe1.py`).
- **Nothing suspicious in member naming**: test names are `data/spam1-test/<16 random chars>.x` only (`profile.training_vs_test.name_suffixes`), so the `.x`/`.1`/`.0` suffixes carry no test-side information; use `spam1-train.labels`, not filename parsing, for the labels file as truth.
