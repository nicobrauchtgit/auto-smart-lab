- Corpus layout: `units/01-spam/spam-detection-with-machine-learning-50-points/data/data/spam1-train/<random16>.{0,1}` plus `.../spam1-test/<random16>.x`. Label is the trailing `.0`/`.1` suffix only, and the file naming carries no test information — parse the label from the last dot, never from content/`ls` order (task.md note; directory listing of `spam1-train/`).
- Text is *pre-tokenized*: lowercased, whitespace-separated, punctuation isolated as its own token (`e - mail`, `ext . 3 - 6245`). Word-level tokenization is already done for you — no NLTK/regex pipeline needed, a whitespace/tokenizer=None vectorizer matches the data (`spam1-train/aabxihdcdotgmase.0`).
- **Spam = coherent prefix + long tail of injected random dictionary words.** `spam1-train/biomolqpzvnnkwvd.1` is 3 meaningful lines (pharma offer, "email removal , go here") followed by ~200 lines of unrelated words (`dissemble incident hawk ababa … optoelectronic fpc potboil …`). This is the central data finding: word-level bag-of-words is deliberately polluted, so the "obvious" TF-IDF baseline is the thing under attack.
- Ham is clean prose throughout (Enron-style, `aabxihdcdotgmase.0` = "associate and analyst program contacts", ~45 coherent lines), but it is **not** noise-free: it ends with a corrupted junk fragment `.g0  dtaokrcyhorfooc.e`. So noise appears in both classes, at very different density/radius. Implication: "garbage present at all" is a fragile feature; *how much* rare/junk vocabulary a document contains is the robust signal.
- Encoding wart: a stray non-ASCII replacement char (`""` in "assistant `""`is marlene muniz") — read files as latin-1/utf-8 with `errors="replace"` and do not strip aggressively or you delete the artifact.
- Train labels look roughly balanced across the observed prefix of the listing (long runs of both `.0` and `.1`), so stratified folds are cheap and correct; verify exact counts before reaching for class weights.
- **Class-conditional unigram language model / per-token mean log-likelihood** (or equivalently, a vectorizer whose vocabulary is frequency-filtered): random-word injection puts mostly *out-of-corpus-frequency* tokens into spam, so average log-probability under a ham-trained LM separates where TF-IDF counts fail. Directly motivated by the noise tail in `biomolqpzvnnkwvd.1`.
- **Vocabulary-richness / rarity statistics as numeric side-features**: type-token ratio, hapax ratio, mean corpus token frequency per document, count of tokens outside a train vocabulary, max run length of consecutive low-frequency tokens. These measure noise *density*, which the `aabxihdcdotgmase.0` vs `biomolqpzvnnkwvd.1` contrast shows is class-dependent.
- **Character n-gram TF-IDF (sublinear/char-level)**: the injected words are dictionary words, so at word level they're indistinguishable from ham content words, but their orthography (rare letter patterns, `ttnci`, `potboil`, `fpc`) is not. Char n-grams also survive the pre-tokenized punctuation oddities.
- **Position-weighted features: subject line + first N lines.** In the spam example only ~3 lines are genuine content before the junk starts; ham keeps meaningful content for the whole body. A separate "prefix" view (subject + first k lines as its own feature block) should be more reliable than the full document.
- Standard word TF-IDF still as a **control baseline** — worth knowing how far the noise costs you, since BACC is reported as a single number and a broken baseline tells you whether noise-robust features are earning their keep.
- Submission format is `data/spam1-test/<file>.x;<0|1>` per line (`task.md`) — build paths from the required literal prefix, not your local absolute paths, and assert the output line count equals the number of `.x` files.
- Optimize/validate the **threshold on Balanced Accuracy**, not accuracy: BACC averages per-class accuracy, so a threshold tuned for plain accuracy can silently degrade the minority class. Use per-class recall (TPR/TNR) in the CV scoring to see which half you're losing.
- Stratified CV with the label parsed from the filename; if you do any subsampling of the huge train set, make it stratified so both class-conditional recall estimates stay meaningful.
- Check for **frequency leakage through the vectorizer's vocabulary**: because spam text is padded with random words, a max_features/IDF cutoff can accidentally encode the attack. Sanity-test a model trained on prefix-only text vs full text — a large gap is evidence you're modelling noise rather than spam.
