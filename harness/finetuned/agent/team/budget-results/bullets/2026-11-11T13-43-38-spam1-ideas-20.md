- **The text is already normalized and whitespace-tokenized**: every file is one `Subject:` line followed by a lowercased body where punctuation is a separate token (`isn ' t`, `$ 7 m`, `http : / / mail . go . com`). So a plain `str.split()` / default sklearn tokenizer reproduces the corpus tokens, and features that exploit punctuation counts (`!` tokens in spam subject lines, `/` in URLs, `@`) are free to compute. *Sources: read `data/spam1-train/aafzhelzmsobdgfm.0`, `data/spam1-train/biomolqpzvnnkwvd.1`, `data/spam1-test/aaaaccnksneuvyqz.x`.*
- **Spam messages contain injected blocks of rare random dictionary words** ("benzoyls 9 bloodbedabbledl escutcheons cosmopolicy duikers"; 20–60-word random-word dumps), while ham reads as coherent prose. This is the word-addition / dictionary-attack family, which is known to substantially degrade bag-of-words NB/SVM spam filters. Practical consequence: a vocabulary cut-off (`min_df`) or IDF down-weighting is not just compression, it is the defence; the *fraction of tokens that are corpus-rare* is itself a usable scalar feature. *Sources: `spam1-train/biomolqpzvnnkwvd.1`, `spam1-train/spjelrotjkrakgiz.1`; [arxiv.org/html/2505.03831v1](https://arxiv.org/html/2505.03831v1) (word addition/substitution most damaging), [usenix.org/legacyurl/exploiting-machine-learning-subvert-your-spam-filter](
- **Ham is internal corporate mail** (Enron-era artifacts: `- - - forwarded by ... / enron on`, `to :`, `cc :`, `subject : re :`, `@ ect`, 2000–2001 dates, $ figures, long quoted threads). Layout-derived features are cheap and highly separable from spam: number of header/footer lines, subject starting with `re :`, body length, quoted-forwarded markers. Risk: these are ham-domain signatures, so they must be paired with content features or they will fail on any new ham domain. *Source: `spam1-train/aafzhelzmsobdgfm.0`.*
- **Spam is content-typologically narrow** — pharma (phentermine/xanax/rx/meds), lottery / advance-fee (winning notification, reference number, notarized, euros, bank), repeated `! ! !`, phone/fax/e-mail/website blocks. Countable regex features per message, plus 1–2 word TF-IDF grams on the subject, cover most of the signal. *Sources: `spam1-train/biomolqpzvnnkwvd.1`, `spam1-train/spjelrotjkrakgiz.1`, `spam1-test/aaaaccnksneuvyqz.x`.*
- **The `Subject:` line is a separate field and short** — represent it as its own document stream (separate vectorizer, or subject + body concatenation) since subject keywords survive the injected noise better than body text. *Source: every inspected file begins with a single `Subject:` line.*
- **Both class listings hit the tool's 1500-item cap** (`data/spam1-train/*.1` and `*.0` each ≥1500 files), so the training corpus is ≥3k messages and roughly balanced — BACC ≈ plain accuracy and class-balancing tricks are unlikely to buy anything. *Source: `find data/spam1-train/*.1`, `find data/spam1-train/*.0`.*
- **The test split is already on disk** (`data/data/spam1-test/*.x`, 16-char basenames) and shows the same preprocessing and the same noise-injection style as training spam — little domain shift expected, so a stratified local split should predict submission BACC closely. *Sources: `ls data/data/spam1-test`, read of `aaaaccnksneuvyqz.x`.*
- Predictions file must be `data/spam1-test/<name>.x;<0|1>` per line — keep paths relative to the task root and never reorder basenames. *Source: task.md.*
- Validate with stratified CV/holdout and report **balanced accuracy** (not accuracy) when tuning; pick the decision threshold on the *validation* BACC rather than defaulting to 0.5 — with near-balanced classes the threshold sweep is where the last points are. *Sources: task.md; class counts above.*
- Deduplicate train/test by content hash before splitting; with 3k+ messages from a few public corpora, near-duplicates inflate CV and explain "submission dropped" surprises. *Source: `data/spam1-train`, `data/spam1-test` listings.*
- Prefer sublinear-TF-IDF (norm='l2', smooth_idf) over raw counts so the long Enron threads don't dominate short spam; keep word grams plus char n-grams to survive the injected dictionary noise. *Sources: `smartlab-spam.txt` slide 4 ("experiment with different feature maps … `sklearn.feature_extraction.text`", start from default KNN/SVM/RF, do model selection); noise-injection observation above.*
- The slides expect scikit-learn + NumPy only, and there is no per-estimator recipe given — the graded axis here is the feature map, so log feature variants (subject-only / body-only / char n-grams / metadata side-cars) as separate ablations. *Source: `resources/smartlab-spam.txt` pages 2, 4.*
