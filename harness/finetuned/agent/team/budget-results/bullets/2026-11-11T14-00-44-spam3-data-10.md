- 3561 training members / 2757 test members, ~76 MB and ~59 MB uncompressed (`training.inventory`, `test.inventory`). Each member is one whole web-page file with a 16-char random lowercase name plus label suffix (`.0`/`.1`; `.x` for test) (`research/inspect.py` name listing, `training_vs_test.name_suffixes`).
- Class balance 3007 : 554 (84.4 % / 15.6 %) — spam minority; balanced accuracy is the metric, so per-class recall matters more than accuracy (`training.targets`).
- The labels file text matches zip member order 1:1 (`research/inspect.py` "label file matches zip order: True").
- The **training zip contains a non-document entry**: one member has a 20-char name (`name len dist train: [(18, 3561), (20, 1)]`) and ends in `.labels` — a script iterating all members as documents dies with `ValueError: invalid literal for int() ... 'labels'` (`research/dupes.py` traceback). Filter by `.0`/`.1` suffix, not by count.
- Content types are not uniform: 3392 html / 166 text / 2 email / **1 binary** in train, 2620 html / 135 text / 2 email in test; UTF-8 fraction 0.9992 (train) / 0.9996 (test) (`training.content_types`, `test.content_types`). One member will fail strict UTF-8 decoding.
- Many pages declare `charset=iso-8859-1` or `windows-1252` in a `<meta>` while raw bytes are decoded as UTF-8 with replacement in my check; declared-charset decoding beats assuming UTF-8 (`research/inspect.py` `charset` fields, e.g. `whthxqhbajdlkhgz.0`, `pxbqmcoowgvaxhcs.x`).
- **No duplicates inside either split** (distinct contents = population in both, `training.duplicates`, `test.duplicates`), and exact content overlap between train and test is 0.0 (`training_vs_test.exact_overlap`). But eyeballing samples I saw what look like **the same page in both splits under different names** — test `gfgixcmzlmncmtej.x` vs train `whthxqhbajdlkhgz.0` (identical eBay/`execeurope` shop markup and JS comments) and test `cuxrrsquczcfbfzu.0`-style XHTML vs train `awnunypkubgfkvzy.0` (`research/inspect.py` TXT dumps). My normalized-whitespace duplicate sweep to confirm this crashed before printing, so treat as **unverified near-duplication across splits**, i.e. the exact-SHA metric would miss it.
- **No ordering leakage**: positive rate is flat across archive quarters (764/126, 751/139, 750/140, 742/149 — `training.order_leakage`), so member order carries no label information and random CV is fine.
- Size, line and URL distributions are nearly identical between splits (train median 14 823 B / 295 lines / 14 URLs vs test 14 832 B / 308 lines / 14 URLs; `training.sizes` vs `test.sizes`, `training.text` vs `test.text`) — no distribution shift to guard against, and test size quantiles (p05 268, p95 61 748) sit inside the training range.
- **File size separates the classes on its own, without touching content**: spam is smaller and much tighter — median 8 768 B, p75 16 261, p95 22 871, **max 237 510**, vs ham median 15 497, p95 63 182, **max 1 048 589** (`training.sizes_by_target`). Every 4 KB header probe of spam read the full document.
- **Link density separates too**: URL-count median 25 (spam) vs 9 (ham); line-count median 84 (spam) vs 202 (ham); `html_rate` 1.0 for spam vs 0.982 for ham (`training.text_by_target`) — spam pages are shorter, denser in links, and all HTML.
- **The spam class is dominated by one doorway-page generator.** Every sampled spam starts `<html><head><title>info - <phrase></title><meta http-equiv="Content-Language" content="en"><meta name="keywords" content="<phrase>">` followed by body text "websites for <phrase> <phrase> ..." with the phrase repeated (`research/inspect.py`, e.g. `rkxtjdcasxlndhds.1`, `mbdgeethrzdrekwb.1`, `opqiyhmbemtoyaxe.1`). A minority of spam uses a different style (search-result-page-looking, `tgsgyysklovdpaon.1`), so the template is not the whole class.
- The same generator appears in the **test** set (`knoohfilxkqzpxax.x`, `ugxjynzsmciqbkxl.x`, `jsxweudbathesmky.x` in `research/inspect.py`) — the spam generator is not held out.
- Second spam template signal: pages whose `<title>` is `info - X` also carry `meta name=keywords` with X; ham samples instead carry site-specific meta (29 metas in `cuxrrsquczcfbfzu.0`, `img`/`imagetoolbar`/CSS links) and often 7+ hidden-style markers versus 0 in the doorway pages (`research/inspect.py` `meta`, `hidden`, `link_tag` fields).
- The two "email"-typed members and the one binary member exist in both train and test, so header-parsing or strict-decoding paths need to survive 2657/2759 HTML-only cases (`training.content_types`, `test.content_types`).
- Nothing else in the name is informative: names are 16 random letters and the only label-carrying part is the suffix (task note + name listing).
