- Task explicitly invites three feature families — words, links, HTML elements (`task.md`). Treat these as three separate feature blocks that can be concatenated, rather than one flat text vector: content-text, tag/structure, and URL/anchor signals.
- HTML parsing is already available in the declared environment: `beautifulsoup4>=4.15.0` (pyproject deps list in the session preamble). Extract *rendered visible text* separately from raw HTML: the difference between them is itself a feature (hidden text / invisible text is a documented spam technique — keyword stuffing in Ntoulas et al.'s content-analysis paper, https://marc.najork.org/papers/www2006.pdf).
- Word-level: TF-IDF over visible text (char- and word-n-grams both) is the baseline representation the unit itself points to: "Play with text features: sklearn.feature_extraction.text" (`resources/smartlab-spam.txt`, p.4).
- Page-structure features worth trying: tag n-grams / tag-sequence n-grams, tag counts (div/a/img/meta/table), script/iframe counts, DOM depth, ratio of link text to text, ratio of anchor count to content length. These follow the content-feature catalogue in Castillo et al., "A Large-Scale Study of Spam Search Engines" (features listed in Section 4 of the PDF: https://faculty.cc.gatech.edu/~lingliu/courses/cs4440/07Fall/p423-castillo.pdf).
- Statistical page heuristics that the same literature singles out as discriminative or, conversely, as failing on some corpora — worth verifying empirically on *this* data rather than assuming: average word length, fraction of unique words, page length, title/meta-tag mismatch, average anchor length, and number of URL terms (`faculty.cc.gatech.edu` PDF, Sec. 4; also the "keyword stuffing / composite words" discussion in https://marc.najork.org/papers/www2006.pdf). The gatech paper explicitly warns that some content features that separate well on Ntoulas-style data give near-identical spam/ham distributions on their corpus — i.e. run the feature sanity check before investing.
- Language-model features over page text (unigram model likelihood/perplexity) are reported to complement content and link features (Araújo et al., https://nlp.uned.es/~lurdes/araujo/airweb09.pdf). Cheap to add given TF-IDF is already built.
- If only the page HTML is provided (single files per page, no crawl graph — inferred from the data note, "the file names of the training pages end in their label", `task.md`), link-graph propagation / graph-stacking tricks from the WPC literature (see https://scispace.com/pdf/the-classification-power-of-web-features-2ahjynl08y.pdf) are **not** available; only in-page signals are. Anchor/URL-derived features are only usable if they occur inside the page itself — verify by opening a couple of files.
- The filename-internal 16-char IDs (`ygrqhabcfcrpwoyr.0`) carry no signal per the task note ("the ending carries no information about the test files") — do not let a hash-prefix feature leak into the pipeline.
- Metric is Balanced Accuracy = mean of per-class recalls (`task.md`), and the class distribution is strongly ham-majority. Optimize the score directly with **per-class recall, not accuracy**; tune the decision threshold on validation instead of defaulting to 0.5 (threshold-moving: https://www.machinelearningmastery.com/threshold-moving-for-imbalanced-classification; imbalance/threshold discussion: https://arxiv.org/html/2409.19751v1). A single global threshold is the cheapest high-value step.
- `class_weight='balanced'` / sample weighting is a first-order fix, but threshold tuning is the part that actually moves balanced accuracy on an imbalanced set — do both, don't stop at weighting.
- Build a proper evaluation setup with stratified CV (the unit's own tip: "Develop a proper and flexible evaluation setup", `resources/smartlab-spam.txt` p.4, and https://scikit-learn.org/stable/model_selection.html). Because test files are unlabeled and the ending `.x` carries no label hint, all decisions (feature subsets, threshold) must be validated by CV on the labeled training files only.
- Encode train/test preprocessing symmetry explicitly: HTML extraction (tag stripping, lowercasing, entity unescaping, charset handling) must be identical on train and test `.x` files; any fit-on-train vocabulary must be applied with `sublinear_tf`/`min_df` pruning so that noisy test-only junk does not create features absent from training.
- Since only 3 submission attempts and best-of-three is scored (per the unit intro), keep the validation threshold choice conservative: pick thresholds from CV, not from per-fold maxima, to avoid overfitting the score.
