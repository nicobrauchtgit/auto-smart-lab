- `data/webspam-train.labels` has ~3,562 lines in `name;label` form (e.g. `data/webspam-train/ygrqhabcfcrpwoyr.0;0`) — worth counting class shares from that file before choosing any imbalance handling; the task text only says ham dominates (`task.md`).
- Every training item is a *complete raw HTML document*, not pre-extracted text: `ahjcunsykrieihka.1` (spam) opens with `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.0 Transitional//EN">` (~81 lines); `aqfgeiaiqneksweu.0` (ham) is XHTML 1.0 (`<!DOCTYPE html PUBLIC ...>`, ~193 lines). So parsing → text + tag tree is the natural first step (`data/data/webspam-train/*`).
- Ham sample is a real institutional site (title `General elections`, `knowsley.gov.uk` in a `pics-label` meta) with many metadata tags (`DC.title`, `DCTERMS.*`, accessibility/WCAG meta); spam sample is a thin gateway page (`daily newspaper sport Results ezze`) built from nested `TABLE`/`FORM` layout with hidden `INPUT TYPE=hidden` fields. This contrast is the strongest lead: markup *quality and structure* may separate classes more reliably than vocabulary.
- Test split is present at `data/data/webspam-test/` with `.x` suffix; filename labels must never enter features (`task.md` data note — the suffix carries no test-side information).
- No `profile.json` exists in the unit folder (only `meta.json`, `prompt.md`, `data/`); `research/` is empty, so no prior code to reuse.
- TF-IDF over *visible* text after stripping tags/scripts/comments, word uni+bigrams — slide tip "play with text features: sklearn.feature_extraction.text" (`resources/smartlab-spam.txt`, p.4) matches content-analysis practice for spam pages (`marc.najork.org/papers/www2006.pdf`).
- Char-level n-grams on the same text as a second view, to catch obfuscated/keyword-stuffed text that word tokenization normalises away.
- Invisible-text ratios: keyword mass inside HTML comments, `alt=` attributes and `meta keywords` relative to rendered text — the canonical "keyword stuffing in invisible content" signal (Ntoulas et al. §4.5, `marc.najork.org/papers/www2006.pdf`; survey `arxiv.org/pdf/1210.3131`).
- Page compression ratio of text (gzip/bz2 size ratio) and page-length/word-count features; spam pages show anomalously low redundancy and different length distributions (`arxiv.org/pdf/1210.3131`; `faculty.cc.gatech.edu/~lingliu/courses/cs4440/07Fall/p423-castillo.pdf` lists compression rate + fraction of visible text).
- Link/anchor features extractable from HTML alone: `<a>` count, external vs internal hrefs, hrefs containing `?`/`=` (dynamic URLs), anchor-text length and anchor-words-to-page-words ratio, plus counts of anchor text that is digits / punctuation / a bare URL / empty (`faculty.cc.gatech.edu/~lingliu/.../p423-castillo.pdf`; `nlp.uned.es/~lurdes/araujo/ieee-tifs10.pdf`).
- External-domain vocabulary of hrefs/srcs (TLD mix, `.gov`/`.edu` presence, repeated host names) as a small categorical/bag-of-domains feature — the crawl looks UK-centric, so TLD/host patterns are plausibly discriminative; the pages' own URL is unavailable, so this is the only "link" information in the corpus (`data/data/webspam-train/*` inspection).
- Markup-structure features: tag-type counts and tag bigram/sequence n-grams, max nesting depth, tags-per-word ratio, presence/absence of `<!DOCTYPE>` + strictness (Transitional vs XHTML), count of `<meta>`/`<script>`/`<style>`/hidden `<input>`, template/generated-site fingerprint (`marc.najork.org/papers/www2006.pdf` describes HTML-structure features as content-based spam signals).
- Simple text statistics known to separate spam pages: word repetition / high-frequency-term ratio, digits-in-text fraction, uppercase ratio, non-ASCII/charset hints from `meta http-equiv="charset=iso-8859-1"`, and language of visible text (`arxiv.org/pdf/1210.3131`).
- Structural n-gram / "site template" view: many spam pages are machine-generated variants, so a representation over tag paths or over href *patterns* (scheme, path depth, extension) can fire where bag-of-words misses (`faculty.cc.gatech.edu/~lingliu/.../p423-castillo.pdf`, content features from Ntoulas).
- Balanced accuracy is the mean of per-class recall (≈ mean of TPR and TNR), so nothing but class-wise recall matters; pick the decision threshold on out-of-fold scores rather than the default 0.5 (`scikit-learn.org/stable/modules/model_evaluation.html`, `scikit-learn.org/stable/modules/classification_threshold.html`).
- Threshold calibration alone tends to move balanced accuracy more than class weights alone; if you add weighting, verify both recalls on held-out folds (`arxiv.org/html/2409.19751v1`).
- Stratified K-fold over the 3.6k labeled pages, with a duplicate/near-duplicate check between train and the folded-out set — spammer templates recur, so a leaked template pair inflates scores and hurts the hidden `.x` split (corpus inspection; slide 4 tip "develop a proper and flexible evaluation setup", `resources/smartlab-spam.txt`).
- Two-stage feature pipeline (text view + numeric structural view) joined before the classifier — HTML pages differ wildly in size, so keep the numeric block independent of vocabulary drift.
- Use a lenient HTML parser and guard against truncated/malformed documents and non-UTF-8 bytes (the corpus declares `iso-8859-1`), otherwise per-file crashes silently drop features or whole pages (`data/data/webspam-train/*` headers).
- If a page fails to parse or has no visible text, emit a sentinel vector instead of skipping it, so train/test feature counts stay aligned.
