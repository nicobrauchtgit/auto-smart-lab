- **`php-train.zip` contains 658 members, not 657**: `php-train.labels` (23 652 B) is stored as a member of the training archive itself, so iterating `ZipFile.namelist()` yields 658 paths and includes a non-script file (`research/inspect.py`, output `research/inspect_out.txt`; profile `training.inventory.samples`=657 counts only scripts).
- **Every file is CR-only, zero LF**: 240/240 sampled members (both splits) had `lf=0` while `cr` ranged 1…3501/6951 (`research/inspect_out.txt`). This fully explains profile `training.text.lines` and `test.text.lines` = all 1 line — line-based features must split on `\r` (or `splitlines()` with `\r`), or every sample collapses to one line.
- **File names are random 16-char lowercase strings with no language/extension signal**: only suffix is the family digit (`train`) or `.x` (`test`); `test.name_suffixes`={"x":355}, `training.name_suffixes`={"1":538,"2":25,"3":21,"4":73} (profile key `training_vs_test.name_suffixes`). Names match labels exactly (0 mismatches, `research/inspect.py`).
- **Severe imbalance**: 4 families, sizes 538/73/25/21 — 82% of training is family 1 (`training.targets`, profile; confirmed by labels). Small families risk collapsing into the giant one; no singletons.
- **Archive order carries no family signal**: family 1 is spread evenly over all four quarters (138/130/130/140) with 2–24 of the others in each quarter (`training.order_leakage`) — nothing to exploit, but also families are not blocked.
- **Families are visually distinct in language/prefix** (`research/inspect.py` output): fam 1 = 36–105 KB PHP webshells opening with `<?php` + banner comment blocks, `fsockopen`, `rand(`, `count(`; fam 2 = Perl, opening `#!/usr/bin/perl` (in one variant glued to `use HTTP::Request;`), `sub`/`use`/`passthru`/`exec`; fam 3 = 169 B…1.8 KB small obfuscated stubs (`eval`+`gzinflate`+`base64_decode`, `error_reporting(0)`); fam 4 = ~1–2.4 KB `eregi`/`ex("id")` shells, some opening in raw HTML (`<title>Google Bypass</title>`).
- **Magic-byte-prefixed and encoded variants are real traps**: some fam-3 files start with `GIF89a\x01…` before `<?php` (profile `training.content_types.categories`: gif 8, binary 39 of 657; `utf8_fraction` 0.875 → ~82 members fail UTF-8 decode, so read as `latin-1`/`errors="replace"`); test has gif 8 **and jpeg 4** (`test.content_types`), a category absent from training. Some members open with a UTF-8 BOM (`\xef\xbb\xbf<?php`, `research/inspect_out.txt`).
- **`<?php` presence does not separate PHP from Perl**: two fam-2 (Perl) members each contain 2×`<?php` and 8×`?>` inside code, so tag counting is not a language feature (`research/inspect_out.txt`).
- **Same-family members are near-identical, not exact duplicates**: two fam-2 members match on dozens of token counts (`<?php`:2, `eval`:1, `base64_decode`:14, `$_`:82, `while`:34, `sub` 61–62) and two large test members likewise (`array(` 279/240, `mysql` 118/118, `htmlspecialchars` 158/147) despite profile reporting `distinct_contents`=657/355 and 0 duplicate groups — i.e. intra-family variation is cosmetic, and near-neighbour similarity (not hash identity) is the usable signal.
- **No cross-split leakage**: `training_vs_test.exact_overlap` fraction 0.0, no duplicate content within either split, and no exact-duplicate groups with conflicting labels (`training.duplicates`, `duplicate_target_conflicts` = 0).
- **Sizes overlap but test is heavier-tailed**: train median 47.8 KB / p95 184 KB / max 240 KB vs test median 41.2 KB / p75 161 KB / p95 191 KB / max 584 KB (`training.sizes`, `test.sizes`); test spans 495 B…584 KB (`test.inventory.total_bytes` 31.25 MB, train 48.8 MB) — read sizes are fine, but any character n-gram matrix on the full test split is large, so keep features sparse/truncated.
- **Test content looks like the same idioms as training even though families differ**: sampled test members show c99/kaMtiEz-style PHP shells with `mysql` 108–118, `exec(` 32–40, `$_` 24–133, `eval`+`base64_decode`, plus smaller obfuscated and HTML-leading files (`research/inspect_out.txt`, sizes 495 B→584 KB; profile `test.text.urls` median 4) — unsupervised grouping on the test split must rely on content idioms, not training-family centroids.
