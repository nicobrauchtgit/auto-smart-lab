- `php-train.zip` has 4 families with sizes 538 / 25 / 21 / 73 (`training.targets`) — one family holds 82% of the data, smallest family has 21 files; labels `1..4`, no singletons, no label conflicts (`training.duplicate_target_conflicts`). Test has 355 files (`test.inventory`).
- `php-train.zip` actually contains **658 members**, not 657: the 658th is a dotless member named `labels` (23,652 bytes = the same size as the standalone `php-train.labels`) — must be filtered out, otherwise it becomes a phantom "family" (my `research/inspect.py` produced a bogus `"labels"` group of n=1).
- Basenames are 16 random lowercase chars (`data/php-known/fajwlhnykclfnmix.1`), so the name carries no signal except the `.family` suffix; the profile's `training_vs_test.name_suffixes` confirms suffix = family size exactly.
- **Line endings are CR-only, never LF.** Every member reads as "1 line" in `training.text.lines` / `test.text.lines`, but the files are not minified: byte inspection found 0 `\n` and hundreds–thousands of `\r` per file (`research/samples.py`: 1427 CR / 149328 bytes in `wjacnvqquuoifcce.1`; `research/test_stats.py`: `cr_only` 299/355, `lf` 0/355). Splitting or tokenizing on `\n` gives one giant blob.
- 74/657 train and 56/355 test files have **no line terminator at all** — genuinely single-line compact scripts (`research/test_stats.py`, `research/inspect.py` per-family `nl0`).
- Exact-duplicate counts are 0 in both splits (profile `*.duplicates`), but after mapping `\r`→`\n` and collapsing whitespace runs, 13 training files collapse into 5 groups and 7 test files into 3 groups (`research/dupes.py`) — whitespace-only twins exist.
- Family 2 is 100% Perl (`#!` shebang, all 25; also 10 of family 1) with no `<?php`; family 2 has no PHP tags at all (`research/inspect.py`). Test contains **0 shebang files** and only 3 with `use ` in the first 400 bytes (`research/test_stats.py`) — the unknown set looks PHP-only.
- Test: 76/355 contain `class pBot`, 13 start with `<html`, 25 have no `<?php` within the first 3 KB; several use `<?` short tags (`<?if (` at byte 0 of `kizyfaxjpnupjfrs.x`) so a `<?php`-only regex under-counts. `<?php` is present somewhere in 330/355.
- Content-type mix differs: `training_vs_test`/profile `training.content_types` (39 "binary", 8 gif) vs `test.content_types` (8 gif, 4 jpeg); `html_rate` 0.887 train vs 0.547 test.
- The gif/jpeg members are containers, not images: the script payload follows the header — `<?php` at offset 41–46 in gifs, `#!` at 3581 plus `<?php` at 10851 in the jpegs, payload = essentially the whole rest of the file (`research/dupes.py`). A text-only extractor silently loses them.
- Training's 8 gif members split 4/4 across families 3 and 4 (`research/inspect.py`), so image magic is not a family indicator.
- Per-family byte ranges (`research/inspect.py`): fam1 3,570–204,964 (avg 82 KB), fam2 55,436–113,900, fam3 169–47,645, fam4 477–240,159. Test max 584,251 exceeds every training file, and test p75 160,851 (`test.sizes`) is well above train p75 113,654 — unknown files skew larger.
- Big files are partly `#`/`*` banner padding and trailing `#` runs (`research/samples.py` tail dumps), but padding is *not* uniform: median `#` byte share is 0.002 (train fam1) / 0.001 (test), median code density after removing `#`-comments and whitespace 0.655–0.916 train, 0.818 test. So raw file length is partly a size feature but heavily noise-dependent.
- Obfuscation is the norm: `eval`/`base64_decode`/`gzinflate`/`assert` in 284/355 test files; `base64_decode` in 320/538 (fam1), 24/25 (fam2), 34/73 (fam4) (`research/test_stats.py`, `research/cross.py`).
- Tokens appearing in ≥70% of a family and essentially absent elsewhere (`research/signatures.py`): fam1 = IRC bot (`chanserv` 513, `vonick`, `anick`, `tsunami`, `slaps`, `offsetc`, `err_num`); fam2 = Perl-only syntax (`elsif`, `sysread`, `unless`, `xmltgt`); fam4 = web-shell exec chain (`pclose`/`popen`/`ob_start`/`function_exists`/`passthru`, 62/73).
- **Family 3 yields no such token at all** and its 21 files pool to only 492 distinct 32-byte windows vs 7,9567 for fam1 (`research/cross.py`) — that family is small and internally heterogeneous, so the reference grouping may not be clean; treat it as a calibration caveat, not a data error.
- On 32-byte normalized windows, only 38/355 test files reach ≥10% overlap with any training family and 317/355 sit below 5% (`research/cross.py`); `training_vs_test.exact_overlap` is 0. The unknown set is content-disjoint from the known families — training serves for developing/calibrating the method, not for carrying label structure over.
- `training.order_leakage`: family 1 appears in all four quarters of archive order (138/130/130/140), so ordering neither leaks labels nor helps.
