- Character/word n-gram bag over *normalized* source, TF-IDF-weighted, cosine similarity: works because these are text scripts, and n-grams survive identifier renaming. Character n-grams + cosine are the reported winner in style/authorship clustering on similar small text corpora (https://ceur-ws.org/Vol-1609/16090984.pdf); byte/char n-gram cosine is also the backbone of a whole-text classifier (http://www.cs.cmu.edu/~ralf/papers/brown-tsd13.pdf).
- Two-stage read-then-normalize: strip whitespace/comments, lowercase, collapse literals (`"..."`→STR, digits→NUM, `$var`→VAR) so variant families of the same shell line up; then n-grams on both raw and normalized text and concatenate views. Justification: webshells in this corpus are heavily obfuscated wrappers, so raw-text distance alone misses the payload (https://scantitan.com/malware-code-analyzer — "encoded eval", "layered decode chain", "character building"; https://github.com/bediger4000/php-malware-analysis/blob/master/webshells/wso_in_depth/README.md — same shell family evolves across versions, so only conserved features are stable).
- De-obfuscation expansion as a *feature source*, not just preprocessing: iterative base64/gzinflate/gzuncompress/str_rot13/hex decoding of string literals and hashing the decoded layer's n-grams. Real PHP webshells from 2010–2012 honeypot captures are `eval(gzinflate(base64_decode(...)))` chains several layers deep (https://scantitan.com/malware-code-analyzer, https://github.com/bediger4000/php-malware-analysis/blob/master/webshells/wso_in_depth/README.md).
- Behavioural/vocabulary vector from static string and call mining: which dangerous PHP functions appear (`eval`, `base64_decode`, `str_rot13`, `preg_replace`, `file_put_contents`, `curl_*`, `system`/`exec`/`passthru`), C&C command set (file manager, SQL console, self-delete, bind/back-connect), POST parameter names, and language markers (Russian-language shells are a known lineage signal) (https://huntress.com/threat-library/malware/php-webshell, https://github.com/bediger4000/php-malware-analysis/blob/master/webshells/wso_in_depth/README.md). These are the features that transfer to *unseen* families, unlike surface text.
- Cheap structural signal worth adding: line/byte length, `<?php` vs raw Perl shebang, ratio of comment/HTML text to code, presence of one giant encoded blob, count of distinct functions defined. Task says the corpus mixes PHP and Perl (task.md), so a language/capability flag should gate other features.
- If AST features are wanted, no PHP/Perl parser is declared in this environment (pyproject deps list only sklearn/scipy/pandas/torch/etc.); either approximate tokens with regex or add a parser package via the env manager — decide deliberately, don't assume `tree-sitter`/`phply` exists.
- Calibrate the clusterer on the 657 labelled files by running the same feature+cluster pipeline with labels hidden and scoring against `.1`/`.2` family suffixes (task.md says names encode family) — tune n-gram width, min_df, and merge threshold against ARI/pairwise-F1 rather than silhouette; a density-based method is preferable because the number of test families is unknown (https://arxiv.org/html/2611.02380v1 discusses HDBSCAN/DBSCAN for malware families; https://scikit-learn.org/stable/modules/clustering.html#hdbscan for the density-scale argument).
- Prefer cosine distance + density/agglomerative-average-linkage with an explicit distance threshold, plus a "noise" label option, over k-means: sparse TF-IDF, unknown k, and heterogeneous family sizes (arxiv survey + sklearn HDBSCAN page above).
- Expect asymmetric pairwise-metric costs and control for both failure modes explicitly: report split-rate (over-fragmentation) and merge-rate (over-merging) separately on train before touching test; single-linkage is tempting for variant chains but tends to chain unrelated shells into one blob.
- Build the vocabulary *transductively* over train+test combined with a `min_df` guard, then keep train only as an evaluation set: test families are disjoint from train (task.md "families in the two datasets are different"), so train-derived vocabulary/centroids carry no information and may bias against new families.
- Guard against label leakage via the `.x` filename suffix and via near-duplicate files: deduplicate exact copies (identical content → same group by construction) and confirm no feature reads the path (task.md filename note).
- Output is per-file group number; emit a deterministic, reproducible group numbering and keep singletons as their own group rather than forcing a "noise = 0" bucket, since the score counts intra/inter pairs of true families.
