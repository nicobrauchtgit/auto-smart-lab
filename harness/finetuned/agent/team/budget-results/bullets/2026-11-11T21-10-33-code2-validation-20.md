The dev measurement is not inflated by the member-name family suffix either: features come only from member content (`tasks/code2.py:14`, `tasks/code2.py:26`), and the pipeline returns 25 groups where a name-reading pipeline would score perfectly on dev and vacuously on `.x` test names.
- `ok:` output domain is valid and reproducible. 559 int group ids for 559 rows, all finite (`tasks/code2.py:28` returns `fit_predict` labels), and sorting rows by `id` reproduced `v_measure=0.4032` exactly (`checks/code2/check_clustering_quality.py`) — average-linkage agglomerative clustering is deterministic and order-invariant.
- `advice:` the shipped `distance_threshold=0.8` (`tasks/code2.py:22`) over-splits badly on the dev corpus: 25 clusters for 2 true families (538/21), homogeneity 0.979 but completeness 0.254, v-measure/AMI 0.403, ARI 0.492, with one 502-member cluster and 13 singletons (`checks/code2/check_structure.py` — this is the grouping quality, not correctness; the trial's `fit`-side path was not exercised, see the first bullet). Because cosine distance on TF-IDF of PHP tokens sits far below 0.8 for same-family variants, the same threshold on the 355 unseen scripts will slice true families into many singleton groups, so the trial's measured score is probably a threshold artefact rather than a ceiling of the representation.
- `advice:` the pipeline has no size/scale guard — `fit_predict` densifies 20 000 features via `features.toarray()` (`tasks/code2.py:26-28`), which is fine at 559–657 rows but leaves the run sensitive to the (larger) hidden split; a sparse path would be cheap insurance.
